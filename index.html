Research & limitations

How this works

Innocent names can be caught by substring restrictions, a frustration raised in community discussion (motivation, not technical evidence).

From the bundled table to candidates

For Steam build 26175237, a read-only extractor locates the bundled table, verifies the container and extracted chunk digests, and checks its row structure. Candidate plaintexts are verified against MD5 of the UTF-8 bytes of phoenix followed by the candidate. Hashcat can discover candidates; a verified preimage is not decryption or proof of the original capitalization. Recovery counts are calculated from the current repository inputs.

How names are checked

The active rows are those for the selected game locale plus all always-check rows. A character's combined first and last name is checked exactly, then the last and first names separately in substring mode. A beast name uses substring mode. In substring mode hyphens, apostrophes and backticks become spaces; short separate tokens are checked when there are multiple tokens, then spaces are removed and the compact name is checked whole if at most three UTF-16 units, or as every substring of four or more units otherwise. Candidates are lowercased, the traced special sequence is removed, and salted MD5 is compared to every active hash. Every hit is reported, even when its plaintext was not previously recovered.

What this cannot promise

This is an offline model of the traced bundled restriction check, not observed in-game approval. The game may replace the list online or apply other naming rules. Native Unicode casing and indexing equivalence is not established; non-ASCII results are approximate. No proprietary game assets are included.

Reproduce and inspect

Use an owned matching installation and the pinned decompressor described in the guide. These commands are examples; replace the installation and wordlist paths for your system.

python3 tools/extract_table.py \
  --paks "$HOME/path/to/Hogwarts Legacy/Phoenix/Content/Paks" \
  --unoodle "$HOME/.cargo/bin/unoodle" \
  --output "$HOME/wizardwords-extraction"
hashcat -m 20 -a 0 --outfile-format 1,2 \
  -o new-matches.txt public/data/language-segments/all/unresolved.hashcat \
  /path/to/your-wordlist.txt
npm run data:build
